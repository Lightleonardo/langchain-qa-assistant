# LangChain Q&A Assistant

A basic Python assistant that accepts questions and returns answers using LangChain and an OpenAI-compatible API (OpenAI or OpenRouter). It keeps a short conversation history, handles empty input and API errors gracefully, and never hard-codes your API key.

## What it does

- Accepts questions from a user.
- Answers through a `PROMPT | llm | StrOutputParser()` LangChain chain.
- Uses a clear prompt template (system message + conversation history + question).
- Maintains a short conversation history (last 6 messages = 3 Q/A pairs).
- Returns a friendly message for empty/whitespace input without calling the model.
- Catches API errors (auth, rate limit, connection, status) and reports them friendly.
- Reads the API key exclusively from an environment variable.

## Setup

```powershell
# 1. Clone the repo
git clone https://github.com/Lightleonardo/langchain-qa-assistant.git
cd langchain-qa-assistant

# 2. Create and activate a virtual environment
python -m venv .venv
.venv\Scripts\Activate.ps1

# 3. Install dependencies
pip install -r requirements.txt

# 4. Copy the example env file and add your real key
copy .env.example .env
# Edit .env and replace OPENAI_API_KEY=your-key-here with your real key.
# .env.example is OpenAI-first: leave OPENAI_BASE_URL unset for the OpenAI API.
# OpenRouter lines are commented out - uncomment only if you want to route
# through OpenRouter instead, and use your sk-or-v1... key there.
```

`.env` is git-ignored and never committed. `.env.example` is committed with placeholder values only — **no real key is committed**. Anyone who pastes a normal OpenAI key into an OpenRouter-configured `.env` will get a 401, so keep the two setups separate.

## How to run

```powershell
python assistant.py
```

Type your questions at the prompt; press Ctrl+C to exit.

## How to run tests

```powershell
pytest
```

The test suite (`tests/test_assistant.py`) is deterministic and never calls the OpenAI API — it replaces the model with stand-in chains.

## Endpoints and transparency

The brief targets the OpenAI API. OpenRouter support (setting `OPENAI_BASE_URL` to
`https://openrouter.ai/api/v1`) is a reasonable extension I added on top of that;
it is **not** part of the OpenAI brief. `run_test_questions.py` records the
endpoint used (model and base URL) in `docs/test_evidence.md`, so the evidence
states exactly which endpoint produced each answer.

Whether a gateway such as OpenRouter is acceptable for this assignment is not
something I can decide — please ask your instructor whether using a gateway is
OK before running the evidence against OpenRouter.

| File | Purpose |
|------|---------|
| `assistant.py` | Core assistant: prompt, chain, model, `ask()`, interactive loop |
| `run_test_questions.py` | Runs five live test questions and writes `docs/test_evidence.md` |
| `tests/test_assistant.py` | Deterministic tests (no real API calls) |
| `conftest.py` | Makes `assistant` importable from `tests/` under pytest |
| `docs/prompt_and_chain.md` | How `PROMPT | llm | StrOutputParser()` works |
| `docs/errors_risks_limitations.md` | Errors handled/not handled, risks, limitations |
| `docs/test_evidence.md` | Generated by `run_test_questions.py` (date, model, answers, judgments) |

| `.env.example` | Committed placeholder env values (no real key) |
| `.env` | Your real key (git-ignored, never committed) |

## Python version

Developed and tested with Python 3.13.

## Secrets

No real API key is committed to this repository. `.env` is listed in `.gitignore` and `.env.example` contains only placeholder values. Before pushing, run:

```powershell
git check-ignore -v .env
git grep -n "sk-"
git log --all -S"sk-" --oneline
```

All should show no secrets.
